有关控制器的若干理解（一）

本文最后更新于 2026-05-13T17:03:13+08:00

  计算机组成原理也被称作CO (Computer Organization) 。因此，在本分类的所有文章当中，我将使用CO来指代“计算机组成原理”。
  这个分类中的文章主要用来记录我对于这门课内容的理解并帮助我整理思路，也可以供各位用作复习参考。因能力有限，文章中可能出现错误，欢迎各位批评指正。

前言

  计算机通过连续执行每一条机器语句而实现全自动工作，我们也把每一条机器语言的语句叫做机器指令，而又将全部机器指令的集合称为机器的指令系统。因此，机器的指令系统集中反映了机器的功能。
  本文的参考教材为唐朔飞编写的《计算机组成原理（第三版）》。

指令的一般格式

  对于每一条指令，我们必须要明确操作的类型，以及要操作的数据。因此，每一条指令由操作码（ $OP$ ）和地址码（或操作数， 统记为 $A$ ）组成。前者指明这一条指令要做什么操作，后者指明要操作的数据的地址或数据本身。显然，操作码的位数反映了机器允许的指令条数。若机器的指令字长为 $16$ 位，而操作码占 $4$ 位，那么该机器可以有 $2^{4}$ 条不同的指令。
  指令的操作码位数可以是固定的，也可以是变化的。对于刚刚给出的例子，如果操作码和地址码等长，那么一条指令可以有三个不同的地址码，也就是可以拥有 $2^{4}$ 条三地址指令。但并不是所有的指令都需要三个地址。因此，我们可以保留若干个操作码作为标识，然后就可以将一个地址码变为操作码。例如，如果操作码部分我们保留 $1111$ 不使用而是作为二地址指令的标识，则以 $1111$ 开头的指令我们就可以认为是二地址指令。这时，原来的操作码和一个地址码共同构成了一个新的操作码，那么我们就有 $2^{4}-1$ 条三地址指令和 $2^{4}$ 条二地址指令。如果我们再保留 $1110$ 不使用而同样作为标识，我们就有 $2^{4}-2$ 条三地址指令和 $2 \times 2^{4}$ 条二地址指令。我们可以在此之上进行进一步扩展，得到一地址指令和零地址指令。这种扩展方式叫做等长扩展技术。

操作数类型和操作类型

  指令的地址码（或操作数）部分指明了指令的操作数的地址或其本身。在计算机中，我们不仅可以对数进行操作，也可以对地址、字符和逻辑数据等进行操作。一般而言，机器字长可以取字节的 $1、2、4、8$ 倍，这样便于字符处理。

  计算机的机器字长反映了计算机一次操作能够处理的数据位数。
  对于 $16$ 位计算机，一个字等于 $2$ 个字节；对于 $32$ 位计算机，一个字等于 $4$ 个字节；对于 $64$ 位计算机，一个字等于 $8$ 个字节。

  对于每个数据，其在存储器中可能存放在一个存储单元中，也可能存放在两个存储单元中。如果存放在两个存储单元中，我们就需要对存储器进行两次访问，并对结果进行一定的调整，才能获得正确的数据。如果所有数据只存放在一个存储单元中，我们称作对准边界；如果有数据不止存放在一个存储单元中，我们称作不对准边界。
  不同的机器虽然操作类型不同，但几乎所有机器都有一些通用的操作。例如，读、写；算术逻辑操作；移位；转移；陷阱和输入输出等。
  我们知道，在计算机中，有一些操作是可以被复用的，我们不需要每次都编写一次。因此，我们可以提前写好这些程序，并在其他程序中进行调用。对于每一次调用，我们先暂停主程序的运行，然后跳转到子程序开始执行，子程序执行完毕后，再返回主程序，根据刚刚暂停的位置继续运行。为了实现这个操作，我们需要用到堆栈。我们知道，在计算机中， $PC$ 保存下一条将要执行的指令的地址，且在每次被访问后，会自动 $+n$ ，即变为再下一条指令的地址，以便于下一次访问（我们假设指令全部顺序执行）。因此，我们在每次调用子程序前，必须将 $PC$ 的值压入栈（即保存断点），然后根据将 $PC$ 的值修改为子程序的入口地址；在子程序返回（即执行完毕）后，我们从弹出栈顶，并将栈顶的数据送入 $PC$ ，主程序就能够继续执行。当子程序调用时，我们执行相同的操作，就可以保证程序能够正确执行。

寻址方式

  对于每一条指令，我们必须根据地址码找到正确的数据，才能保证程序能得到正确的结果。而我们一般认为机器字长、指令字长和存储字长三者等长，因此，在一条指令中，地址码（或操作数）的位数小于机器字长（或存储字长），就导致寻址范围（或数据范围）有限。因此，我们需要考虑不同的寻址方式。为了分辨不同的寻址方式，在指令中，我们规定有若干位的寻址特征标记。而一般情况下，指令的地址码字段都不代表操作数的真实地址（后文称为有效地址，我们将操作数的有效地址记作 $EA$ ），因此我们也将指令的地址码叫做操作数的形式地址，即 $A$ 。
  立即寻址指的是指令的地址码部分就是操作数本身（也称为立即数），因此我们不需要寻址，只需要直接处理指令的地址码即可。这种寻址方式的寻址特征标记是 # 。可见，只要取出指令，我们就可以立即获得操作数，而不必访问存储器。但是，指令中地址码的位数限制了这类指令所能表述的立即数的范围。
  直接寻址指的是形式地址即为有效地址，也就是指令的地址码就是操作数在存储器中的地址，即 $EA = A$ 。这种方式没有限制操作数的范围，也不需要额外计算，在执行指令时只需访问一次存储器。但由于地址码的位数一般小于机器字长，这种寻址方式的寻址范围受到了限制，不能访问所有存储单元。
  隐含寻址指的是操作数的地址隐含在了操作码或某个存储器中。我们知道，对于加法操作，我们需要两个操作数。但在计算机中，我们将其中一个数存储在 $ACC$ 中，所以执行加法操作时，我们只需要一个操作数即可，另一个操作数隐含在了 $ACC$ 中。
  间接寻址指的是指令的地址码给出的是存储器中保存操作数地址的地址，即 $EA = (A)$ 。也就是说，我们第一次根据形式地址访存时，得到的结果仍然是一个地址，表示操作数在存储器中的地址。这时我们根据这个地址再进行一次访存，就能够得到操作数。这种寻址方式在指令执行阶段需要访问两次存储器，但扩大了寻址范围。例如，如果指令字长和存储字长均为 $16$ 位，对于 $8$ 位的地址码，使用直接寻址只能找到 $2^{8}$ 个不同的存储单元；而使用间接寻址，则可以找到 $2^{16}$ 个不同的存储单元。
  寄存器寻址与直接寻址类似，但不同的是，操作数存放在寄存器中。因此，在指令的地址码部分，我们只需给出寄存器的编号即可。这种方式在指令执行阶段不需要访存，而且节省了存储空间，在计算机中得到广泛应用。
  寄存器间接寻址与间接寻址类似，但不同的是，操作数的地址存放在寄存器中。因此我们只需根据寄存器中的数据，取出存储器中对应地址的数据即可。与间接寻址相比，这种方式少一次访存，速度更快，二者寻址范围相同。这种方式利于编制循环程序。
  基址寻址需设有基址寄存器 $BR$ ，这种寻址方式的有效地址 $EA = (BR) + A$ ，即操作数的地址与 $BR$ 中存储的地址有关。与直接寻址相比，这扩大了寻址范围，有利于多道程序。
  变址寻址同样需设有寄存器 $IX$ 。这种寻址方式的有效地址也是 $EA = (IX) + A$ ，但不同的是，在基址寻址中， $BR$ 中存储的基址不变，仅 $A$ 改变；而在变址寻址中， $A$ 不变而 $IX$ 中存储的地址需要改变。变址寻址一般用来编写数组等程序。
  相对寻址一般用于程序的跳转。其有效地址 $EA = (PC) + A$ ，也就是说 $A$ 代表某一条指令相对 $PC$ 中的指令在存储器中的偏移。 $A$ 又称位移量，可正可负，通常用补码表示。
  堆栈寻址要求计算机中设有堆栈。堆栈既可以用寄存器组（称为硬堆栈）来实现，也可以用主存的一部分空间（称为软堆栈）来实现。这种寻址方式下，我们有一个寄存器 $SP$ ，其存储的内容为栈顶元素的地址。也就是说，堆栈寻址也是一种隐含寻址，其地址码隐含在 $SP$ 中；而由于 $SP$ 中存放的是操作数在存储器中的地址，也可视为寄存器间接寻址。每次有元素进栈时，我们使 $SP = (SP) - n$ ；每次出栈时，我们使 $SP = (SP) + n$ 。 $n$ 的取值与主存编址方式和存储字长有关。若主存按字节编址，一个存储字长是 $2$ 字节（即 $16$ 位），则 $n = 2$ 。总之，在每次涉及到栈的操作完成后，我们需要保证 $SP$ 存储的是栈顶数据的地址。

结语

  计算机是一个错综复杂的系统，在合理的安排下，我们才能使计算机的工作有序。
